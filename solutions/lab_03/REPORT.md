def level(result:int,absent:int): 
    if 90 <= result <=100: lvl = 4 # (1) Находится ли result в диап. [90,100]? Да -> выполняем (1) и выходим из ЭТОГО условия. Нет -> идем в (2)

    else: lvl = 1 # (4)  Условия (1-3) не сработали => выполняем ветку (4)

    if lvl != 1 and absent > 3: lvl -= 1 # Новое условие. Если верны оба условия, уровень понижается

### Задание 2. Циклы и базовые алгоритмические схемы

Для анализа списка была создана функция `lool_through()`, которая выполняет два прохода по списку: за первый проход без использования `min()`, `max()`, `sum()` и `list.count()` вычисляются значения переменных `sum` - сумма элементов, `min` - минимальный элемент, `max` - максимальный элемент и `even` - количество четных чисел в списке; за второй проход считается количество элементов, числовое значение которых превышает среднее арифметическое всего списка.

Для реализации линейного поиска числа в списке была создана функция `look_for()`, которая проходится по списку и выводит индекс ПЕРВОГО вхождения(индексы последующич вхождений не выводятся), если соответствующий элемент имеется, или выводит `-1` в противном случае. 

#### Дополнительный алгоритмический эксперимент

Для реализании проверки простоты целого положительного числа `num` была создана функция `is_prime()`, которая проверяет целые числа `i` от `2` до `[num^0,5]`. Если `i` является делителем `num`, перебор прекращается - `num` не является простым числом. Если `num` не делится ни на одно число `i`, `num` является простым числом. 

Проверка делителей только от `2` до `[num^0.5]` является корректной, потому что для любых `a` и `b` таких, что `a * b = num` выполняется и `b * a = num`. Таким образом при переборе сверх `[num^0.5]` пары `a`, `b` начинают повторяться: $a_{i} = b_{dev - i}$, где `dev` - количество делителей числа.

#### Анализ временной сложности для реализованных алгоритмов

| Алгоритм(функция/процедура) | Временная сложность | Затраты памяти | От чего зависит число операций |
|---|---|---|---|
|`look_through(the_list)`| `O(2*n) = O(n)` | `O(1)` - не создается структур, объем которых зависит от входных данных | Число операций зависит от количества элементов массива `the_List`. Сколько элементов, столько сравнений в каждом из циклов. В сумме - `2*n`. |
| `look_for(num,the_list)` | `O(n)` | `O(1)` - не создается структур, объем которых зависит от входных данных | Число операций зависит от удачности входящего массива/числа. Если искомое число стоит на `i`-й позиции в массиве, будет произведено `i` операций. Если `i = n` или искомого числа нет в массиве, всего будет произведено `n` операций. |
| `is_prime(num)` | `O(n^0.5)` | `O(1)` - не создается структур, объем которых зависит от входных данных | Число операций зависит от величины и удачности входящего числа. Если число простое, будет произведено `n//2` операций, где `n` - количество делителей числа. Если число не является простым, будет произведено `i` операций, где `i` - номер минимального делителя числа |

Также стоит отметить:

* Множество подходит для хранения уникальны объектов. Оно основано на хэш-таблице, которая позволяет быстро добавлять, удалять или находить объекты, а также автоматически исключает дубликаты.

* Кортеж можно использовать в качестве ключа для словаря, потому что он является неизменяемым объектом.

* Список нельзя использовать в качестве ключа для словаря, потому что он не является неизменяемым объектом(ключ должен быть постоянным, чтобы определять значение всегда однозначно).

#### Исследование LEGB

Рассмотрим следующий фрагмент:

```python
course = "Math" # GLOBAL

def outer():
    semester = 1  # ENCLOSING
    
    def inner():
        lesson = 5  # LOCAL

        nonlocal semester # Изменяем значение semester из внешней функции
        semester += 1
        
        print(f"Курс: {course}")
        print(f"Семестр: {semester}")
        print(f"Занятие: {lesson}")
    
    inner()

outer()
```

* Переменная `course` является глобальной переменной, потому что она определена вне всех функций.

* Переменная `semester` является переменной объемлющей, потому что она определена внутри функции `outer`.

* Мы можем изменить значение переменной `semester` внутри функции `inner`, используя `nonlocal`.

* Переменная `lesson` является локальной переменной, потому что она определена внутри функции `inner`.

Когда Python видит переменную, он ищет ее в следующем порядке:  
$$Global    ->    Enclosing    ->    Local    ->    Built-in$$

При этом области видимости можно представить таким образом:

```text
┌─────────────────────────────────────────────────┐
│  BUILT-IN (len, print, sum, ...)                │
│  ┌───────────────────────────────────────────┐  │
│  │  GLOBAL                                   │  │
│  │  course = "Math"                          │  │
│  │  ┌─────────────────────────────────────┐  │  │
│  │  │  ENCLOSING (outer)                  │  │  │
│  │  │  semester = 1                       │  │  │
│  │  │  ┌───────────────────────────────┐  │  │  │
│  │  │  │  LOCAL (inner)                │  │  │  │
│  │  │  │  lesson = 5                   │  │  │  │
│  │  │  └───────────────────────────────┘  │  │  │
│  │  └─────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

#### Ошибка изменяемого значения по умолчанию

Рассмотрим следующую ошибку:

```python
def add_result(value, results=[]):
    results.append(value)
    return results
```

Здесь именованная переменная задается *определенным* списком. Он создается всего единожды, и каждый раз при вызове функции он будет меняться, а не создаваться заново.

Исправленный код выглядит так:

```python
def add_result(value, results=None):
    if results is None:
        results = []
    results.append(value)
    return results
```

#### Практическое расширение

Реализованы функции `apply_to_results(operation, values)` и `make_threshold_checker(threshold)`.

* Функция `apply_to_results()` является функцией высшего порядка - она принимает другую функцию `operation` и список значений `values`, применяет функцию к каждому элементу и возвращает новый список результатов.

* Функция `make_threshold_checker()` является фабрикой функций и использует механизм замыкания. Замыкание - это внутренняя функция, которая "запоминает" переменные из объемлющей области видимости даже после того, как внешняя функция завершила свою работу.
  
Рассмотрим следующий фрагмент:

```python
def make_threshold_checker(threshold: float):
    def checker(value: float) -> bool:
        return value > threshold  # threshold сохраняется в замыкании
    return checker  # Возвращает функцию, а не результат её вызова

check_50 = make_threshold_checker(50)
check_80 = make_threshold_checker(80)

print(check_50(60))  # True (60 > 50)
print(check_80(60))  # False (60 не > 80)
```

Переменная `threshold` является переменной объемлющей области функции `make_threshold_checker()`. Внутренняя функция `checker()` использует эту переменную, хотя не определяет её. Когда вызывается `make_threshold_checker(50)`, создаётся новая функция `checker()`, которая сохраняет значение `threshold = 50`. Эта функция возвращается и присваивается переменной `check_50`. Аналогично, `make_threshold_checker(80)` создаёт другую функцию checker `с threshold = 80`, которая присваивается переменной `check_80`. Функции `check_50` и `check_80` - разные.

### Задание 5. Анализатор учебных результатов

Была создана программа, которая анализирует результаты группы студентов и выводит статистику.

#### Тестовые сценарии

| № | Сценарий | Ожидаемый результат | Фактический результат |
|---|---|---|---|

| 2 | Один студент: `{"Анна": [80, 90]}` | Отчёт по одному студенту, средний 85.0, категория "Хорошо" | Соответствует |

#### Декомпозиция программы

1. **Базовые функции** (`mean`, `minimum`, `maximum`, `classify`) — выполняют одну простую операцию, легко тестируются через `assert`.

2. **Функции-агрегаторы** (`student_summary`, `group_summary`, `find_top_students`) — используют базовые функции для построения итоговых структур.

3. **Функция представления** (`format_report`) — отвечает только за вывод, не содержит вычислительной логики.

#### Оценка сложности построения общей статистики

Пусть `n` — количество студентов, `k` — среднее количество оценок у студента.

| Операция | Сложность | Пояснение |
|---|---|---|
| Сбор всех оценок в `all_res` | O(n·k) | один проход по всем оценкам |
| Подсчёт категорий | O(n) | для каждого студента вычисляется `mean` (O(k)) и `classify` (O(1)), итого O(n·k) |
| Поиск топ-студентов | O(n·k) | для каждого студента вычисляется `mean` |
| **Итого `group_summary`** | **O(n·k)** | линейная сложность от общего числа оценок |

Дополнительная память: O(n·k) для списка `all_res` и O(n) для словаря `categories`. Исходный словарь `students` не изменяется.
